# Developer probes

Scripts for judging a change by looking, kept here rather than in a session's
scratch folder so the next person has them. They drive the Chrome already on
the machine: the `.mjs` ones through `../capture.mjs` (install once with
`cd 80_APP/tools && npm install --no-save puppeteer-core pptxgenjs`), the
`.py` ones through `chrome.py` here (a name for the engine's `terrane.draw.browser`, which `--png` shoots drawings with), which speaks the DevTools protocol with
the standard library and needs nothing installed. All expect the app to be
listening on 127.0.0.1:8020 (`python 80_APP/app/server.py`) unless told
`--url`. Pictures land in `out/`, which is not committed.

| Script | What it answers |
|---|---|
| `shots.mjs name=hash ...` | What does this drawing look like now? A PNG per hash through the app's own export, with its size and the zoom the app chose. |
| `opening_probe.mjs out/ URL [stone\|graphite] [view ...]` | What does every drawing open at, as a person sees it? Each view in the estate (or those named) opened in a 1440 by 900 window with the sidebar and the brief as the app leaves them: a line each in `out/<tone>.jsonl` with the zoom it opened at, the zoom it fits whole at, how many pixels a box's name is on the screen, how much of the drawing is in view and the range of box sizes, and a PNG of the window. Run it before and after a change to the opening or the layout, in both tones. |
| `ratio_probe.mjs [view ...]` | How does every drawing fit the sheet? Width, height, ratio and fit zoom per view; run before and after a layout change. |
| `pages.mjs out/ URL name=hash ...` | What does a page look like, window and all? A PNG per name of the whole app as a person sees it, `name=hash\|click:id` pressing a button for the pages a hash cannot reach; for judging the shell rather than a drawing. |
| `drag_probe.mjs out/ URL name=hash\|BOX>TARGET[\|steps]` | What does a drop do? Drags a box with the mouse onto another box or into a boundary (a clear spot in it, found from the drawing), captures the moment before and the chooser it opens, and with `confirm,undo` makes the move and takes it back; `layout=packed` first for a map drawn as tiles. Prints what the chooser said and which boundary the box is drawn in. |
| `mirror_probe.mjs out/ URL [view]` | Does maxGraph draw the canvas where Cytoscape laid it out? Opens a canvas diagram (lending-onboarding by default, made as `arrange_probe.mjs` makes it) with `canvas/engine.js` drawing it, and holds every box to 1.5 pixels of Cytoscape's outline, every shape on screen to maxGraph's own view state, and the count of lines; a PNG of each drawing beside the other. It writes to the model when it makes the diagram: run it on a copy. Any probe here opens the canvas as it was before maxGraph when `TERRANE_CANVAS_ENGINE=cytoscape` is set (`capture.mjs`). |
| `gesture_probe.mjs URL [view]` | Do the canvas's gestures do what they did? Walks a press on a box (the panel names it), a press on bare sheet (it lets go), hovering, three turns of the wheel and a drag on the sheet (with the Hand on maxGraph, where a drag across the bare sheet picks) with a real pointer, on the canvas as Cytoscape takes them and as maxGraph takes them, and holds the two equal; and counts Cytoscape's own `tapstart`, which must stay at none with maxGraph on. Reads lending-onboarding by default (`arrange_probe.mjs` makes it) and writes nothing. |
| `annotate_probe.mjs out/ URL` | Does the canvas draw from scratch? On a new diagram, with a real pointer: a frame, a note typed into, a diamond from the Shapes menu, text and a line joined at both ends; the note restyled from its panel, moved, undone and redone; the diamond deleted and brought back; the diagram opened again, opened as a diagram (read only) and fetched as the engine's picture, each holding the same shapes. Then, on lending-onboarding (`arrange_probe.mjs` makes it), a note by the Lending portal and a line from it, both where they were when the diagram is drawn again, and a line between two records asking what it is; then several records picked by a drag from inside the account round zone eu-west-2b, the bar over them, lined up by their tops, undone, framed with Ctrl+G, the frame carried by its name with the records it was drawn round going as far, one Undo putting the frame and the records back, and the frame undone. It makes diagrams: run it on a copy. |
| `export_probe.mjs out/ URL` | Do the export and the overview draw what the canvas draws? On a new diagram, a frame and a note typed into it: the PNG the export takes (`window.__aacDrawingPng`) holds the note's yellow, at the frame's size with sixteen units of white each way, the sheet back at its own zoom after; and the overview, once part of the drawing is off the sheet, draws the note. Then on lending-onboarding (`arrange_probe.mjs` makes it, `annotate_probe.mjs` puts a note by the Lending portal) the same beside the records, the picture no smaller than Cytoscape's of the estate alone and holding as much strong color, which a mark that did not load takes away. Both pictures and the window land in `out/`. It makes a diagram: run it on a copy. |
| `names_probe.mjs out/ URL [view]` | Do the names on maxGraph's canvas sit where Cytoscape set them? The diagram (lending-onboarding by default, which `arrange_probe.mjs` makes) opened twice at two pixels to the CSS pixel, as the canvas draws it and as the old canvas does (`?canvas=cytoscape`), both at one zoom on one place (`NAMES_ZOOM`, 2 by default); in each box the rows and columns the name's ink takes, pixels near the name's own color, and how far maxGraph's are from Cytoscape's: a line per box and the means. Exits 1 past a pixel either way or with the means leaning, since maxGraph puts an HTML label at a whole unit of the drawing. Writes nothing. |
| `snap_probe.mjs out/ URL` | Does Snap to grid put things on the grid? On lending-onboarding (`arrange_probe.mjs` makes it): the status bar under the sheet saying how the diagram is laid out and what is on it; Snap to grid turned on there and kept in the browser; a record carried an odd distance and let go with its corner on the ten-unit grid; a note drawn with its corner and size on the grid and carried, still on it; Snap to grid off again. It moves a record and draws a note: run it on a copy. |
| `keys_probe.mjs out/ URL` | Does every tool have its key, and does the canvas say them? On lending-onboarding (`arrange_probe.mjs` makes it): N, T, F, L, R, H and V each choose their tool, its button pressed; the toolbar has no Boundary of its own, and B opens Add on its Boundaries tab, which Add closes; "?" opens the sheet of keys over the status bar, Esc closes it, and its button opens and closes it; Ctrl+K's palette lists the canvas's tools first, each with its key, and one is chosen from it by name. Writes nothing. |
| `spacing_probe.mjs out/ URL` | Does a box carried in its boundary find the equal gap? On lending-onboarding (`arrange_probe.mjs` makes it), three subnets in a row in zone eu-west-2b: the last carried off and brought back to three pixels short of the gap the first two have, held there with the two red measures saying its size, then let go at that gap; and Undo puts it back. Then on a new diagram, three notes of its own in a row, 40 units between the first two: the third carried to three pixels short of that, two measures saying 40, let go 40 from the second, and Undo. It moves a box and makes a diagram: run it on a copy. |
| `quick_probe.mjs out/ URL` | Does quick connect draw the next box? With a real pointer: on a new diagram, a shape hovered shows four arrows off its sides, which stay as the pointer goes out to one; the right one pressed draws the same shape 60 units to the right joined by a line, open to type in, and one Undo takes both away; pressed again and typed in, it keeps the words; the arrow below carried to empty sheet draws the next shape there, and the right one carried onto the shape beside it draws only a line. On lending-onboarding (`arrange_probe.mjs` makes it), the Lending portal's right arrow opens Add asking what comes next, and a record of the estate chosen, a line joins the two and asks "What is this line?". It draws and makes a diagram: run it on a copy. |
| `jumps_probe.mjs out/ URL` | Do lines hop where they cross? On a new diagram, a line across and a line down through it, drawn after: the second hops the first once and the first hops nothing; Line jumps in the status bar turned off, nothing hops and the browser keeps it off; on again, the hop is back; the first line moved clear, the second is drawn straight again. Then on lending-onboarding (`arrange_probe.mjs` makes it), the estate's lines hop where they cross. It makes a diagram: run it on a copy. |
| `bends_probe.mjs out/ URL` | Does a straight line bend where it is dragged? With a real pointer, on a new diagram: two shapes and a straight line between them; the line picked shows a handle halfway along it, which carried 80 down bends the line there; the diagram's file keeps the bend under `via`, and the engine's own picture draws the line through it; one Undo straightens it and Redo bends it again; the panel's Remove the bend takes it out; bent again and made square, the bend goes. It makes a diagram: run it on a copy. |
| `around_probe.mjs out/ URL` | Does a square line go around the boxes in its way? On a new diagram: two shapes, a note between them and a square line from one shape to the other: no piece of the line runs through the note, and its turns are the ones the engine's own picture draws; the note moved out of the way, the line takes its plain turns again, straight across; one Undo puts the note back and the line goes around it again. Then on lending-onboarding (`arrange_probe.mjs` makes it), a square line between two notes either side of the Lending portal goes around the portal's box. It makes a diagram and draws on one: run it on a copy. |
| `pins_probe.mjs out/ URL` | Does a line's end stay where it is put on a box? With a real pointer, on a new diagram: two shapes and a straight line between them; the line picked, its end carried over the second shape shows the twelve points it can be held at, and let go on the top middle it is held there, which the file keeps as `to_at` [0.5, 0]; made square, it comes into that point from above, square, as the engine's own picture draws it; the shape moved, the end moves with it; carried off the shape to empty sheet the end stays at a point there, held nowhere; one Undo puts it back. It makes a diagram: run it on a copy. |
| `search_probe.mjs out/ URL` | Does the search box find what a person means? Typed into Ctrl+K's palette with the keyboard: "core ledger" puts the Core Card Ledger first, ahead of the interfaces named for it; "ledgr", misspelled, finds a ledger; "rdbms", an alias of the relational database kind, finds the SQL databases; "led", half typed, finds ledgers; and Enter on the first opens it. A PNG of the palette each time. Point it at a baked static copy too, where the index is a file. Writes nothing. |
| `paste_probe.mjs out/ URL` | Does copy and paste carry what is picked across diagrams? On lending-onboarding (`arrange_probe.mjs` makes it, `annotate_probe.mjs` puts a note by the Lending portal and a line to it): the portal, the note and the line picked and copied with Ctrl+C into the browser; Ctrl+V on the same diagram draws the note and the line again 24 units on, and one Undo takes them away; Ctrl+V on a new diagram places the portal and draws the note and the line joined to it, which the new diagram's file holds. It draws and makes a diagram: run it on a copy. |
| `lock_probe.mjs out/ URL` | Does Lock keep things where they are? On lending-onboarding (`arrange_probe.mjs` makes it, `annotate_probe.mjs` puts a note there): the portal locked with Ctrl+Shift+L, its panel offering Unlock; carried with a real pointer and nudged beside another record, it stays and the other moves; the note locked as it is picked loses its handles, and carried and nudged it stays; one Undo unlocks it; opened again the portal is still locked, and Unlock in its panel lets it go. What an earlier walk left locked it unlocks first. It changes the diagram: run it on a copy. |
| `rotate_probe.mjs out/ URL` | Does a shape of the diagram's own turn? On lending-onboarding (`arrange_probe.mjs` makes it, `annotate_probe.mjs` puts a note there): the note's panel offers Turned; set to 30, maxGraph draws it turned, the diagram's file keeps `rotate: 30` and the engine's own picture turns it about its middle; its handle above it, carried round sixty degrees with a real pointer, turns it to 90; one Undo puts it back; a frame (drawn for the asking where there is none) offers neither Turned nor a handle; locked, the note shows no handle; set to 0, the file says nothing of turning. It changes the diagram: run it on a copy. |
| `part_probe.mjs out/ URL` | Does Add find a part by what each cloud calls it? On lending-onboarding (`arrange_probe.mjs` makes it): Add's search for EC2, Compute Engine and Azure OpenAI, each row named for what was asked and the nearest first; the EC2 row dropped into the AWS zone eu-west-2a, the name it is asked for and what AWS calls it offered; placed, the record's product and its mark. It makes a record: run it on a copy. |
| `arrange_probe.mjs out/ URL [graphite]` | Does a canvas diagram stay where it is put? Makes a diagram of Network Topology with two systems through the canvas's endpoints, then drags a box within its zone, drags a system in from the picker, carries a box into another zone and moves it there, drags a boundary, lays it out again and undoes that; a PNG per step, and a line each on how many positions the file keeps, which boxes moved and how far a drop landed from where it was let go. It writes to the model: run it on a copy of the repository. |
| `place_probe.mjs out/ URL` | Does every page keep a way back and its place? On nine pages, reached by pressing what a person presses: hides the sidebar, captures the window (`<page>-hidden.png`) and says whether a Show the sidebar control is on screen and brings it back; then chooses something (a table, a shelf, a tab), scrolls or zooms, reloads, and says what the reload lost, if anything: the address, the heading, what was chosen, the drawing's zoom and pan, the scroll. Run it before and after a change to the shell or the router. |
| `tour_probe.mjs out/ URL [graphite]` | Does the tour run, start to end, as a first visit sees it? From a cleared browser: the offer on Home, Start the tour, then each step done as its card asks (some by the person's own press, some by Show me) to the end card, a PNG per step and a line each with the card's words, where the ring is and whether the pointer rests in it; then Next and Back, Esc, Not now, Don't offer this again, and Take the tour from Help. Point it at a baked static copy too: there the last step only opens the New menu. |
| `drop_probe.mjs out/ URL FILE [ORG-X] [correct] [graphite] [from=home] [review-only]` | What does a dropped drawing do? Drops a file on New diagram's sheet (or an empty estate's first page) through the browser's own DataTransfer, captures the sheet with the file over it, the page that says what adopting it would add, the corrections ticked, and the canvas after Adopt, and prints what each said. It writes the drawing's records: run it on a copy of the repository, beside a twin adopted with `terrane adopt` to diff against. |
| `err_probe.mjs <hash>` | Why is this drawing blank? Page and console errors from before the first script runs. |
| `live_probe.mjs [base-url]` | Did the deploy land? Marks and the review-pack line on the hosted demo, and any icon the site failed to serve. |
| `watch_ci.sh <sha>` | Are both workflows green on this commit? Waits and prints their conclusions; run it as a background task after a push. |
| `layout_fixture.py [view ...]` | What did the app compute for this drawing? Every node's center, size and box and every boundary's box, read back from Cytoscape into `50_ENGINE/tests/fixtures/layout/` for the packed maps and `fixtures/layered/` for the dagre-ranked diagrams, the latter with the direction the app chose, the axis it ranked each edge along and every routed edge's points; for a tile map, every band, card, grid and tile as the page laid it out, with the lines each name broke into, into `fixtures/tiles/`, `fixtures/elk/` for the small diagrams the app hands to ELK, which `terrane.draw.elk` holds equal through the browser, `fixtures/wheel/` for the hub view's concentric layout, and `fixtures/organic/` for a flat drawing the app laid out with cose after dagre ranked it into a ribbon (captured from a probe view that was not kept; the fixture carries its payload); the app's own PNG lands in `out/`. The Python layout in `terrane.draw` is held equal to these. A fixture whose view is gone (a retired view, a deleted probe) is taken again with `--replay fixture.json ...`, the page handed the payload the fixture holds. |
| `font_metrics.py` | How wide is this text in the app's own face? Every glyph and pair of the shipped faces measured in Chrome into `50_ENGINE/terrane/draw/fonts/metrics.json`; re-run when a face or a weight is added. |
| `svg_shot.py view-or-file ...` | What does the Python drawing of this look like? The sheet from `/api/svg` for a view, or an SVG file on disk such as a committed picture under `70_ARTIFACTS/`, as a PNG at 2x, for reading beside the app's export of the same view. |

The README's own pictures are a separate script, `../screenshots.py`, described in
`80_APP/README.md`; the review pack is the engine's own `terrane pack`.
